# 16 — Risk Register

Status values: `Open`, `Mitigated`, `Accepted`, `Closed`. All seeded `Open` in Phase 0 (none yet
mitigated since no evaluation logic exists).

| Risk | Status | Notes |
|---|---|---|
| Benchmark bias (tasks favor a particular system) | Open | Mitigation: quality rules in [[07-benchmark-strategy]]; scientific integrity rule in [[00-project-charter]]. |
| Baseline weakness (native agent baseline set up to fail) | Mitigated | At Phase 6 remainder: the real comparison run pairs the *same* `LlmSolvingAgent` with every condition's `ContextProvider`, including native — the old deterministic, always-`INCOMPLETE`, never-edits-code `NativeAgent` is explicitly excluded from the real comparison (ADR-013 in [[14-decisions]], [[09-experiment-strategy]]). Not fully Closed: no live run has been executed yet to confirm the native baseline behaves reasonably in practice, only that the design no longer conflates agent capability with context quality. |
| Evaluator bias (LLM-as-judge over-trusted) | Open | Mitigation: LLM-as-judge is secondary-only — [[06-evaluation-methodology]]. |
| Future-knowledge leakage (temporal contamination) | Open | Mitigation: temporal integrity policy — [[06-evaluation-methodology]], [[07-benchmark-strategy]]. |
| Nondeterminism across runs | Open | Mitigation: repeated runs (3 per condition×task in the Phase 6-remainder comparison design), recorded seeds where applicable — [[10-reproducibility]]. Now concretely live, not just hypothetical: `LlmSolvingAgent` calls a real, sampling LLM backend, so run-to-run variation is an actual, not merely theoretical, source of noise the repeated-run statistics (Phase 7) must absorb. |
| Agent/model version drift invalidating comparisons | Open | Mitigation: version metadata recorded per run — [[10-reproducibility]]. Partially unaddressed: `Run.metadata.modelName`/`modelVersion` are still not populated for `LlmSolvingAgent` runs (see [[20-next-actions]] item 2) — `Run.metadata.agentName` embeds the provider/model as a stopgap, but the dedicated fields remain empty until `runHarness.ts` is extended. At Phase 11: `docs/REPRODUCING.md` now surfaces this gap to a public/external reader (not just this internal risk register), explicitly phrased as an open, unresolved limitation — publishing that guide does not close this row. |
| Benchmark overfitting / metric gaming | Open | Mitigation: multi-evidence outcome evaluation, no single composite score — [[08-metrics]]. |
| Stale engineering evidence in context artifacts | Open | Assessed at Phase 6: ECC's documented package contract does carry a per-evidence-item `provenance.freshness` (`current`/`stale`/`unknown`) field, but `EccContextProvider` currently stores the whole validated package as opaque `ContextArtifact.content` text — nothing yet reads that field to flag or downweight stale evidence. Tracked as a future metrics/evidence-pipeline enhancement, see [[20-next-actions]]. |
| ECC CLI as an external, versioned dependency EEP does not control | Open | New at Phase 6. `EccContextProvider` validates every invocation's output against EEP's own schema mirror (`eccPackageSchema.ts`) and fails loudly (`EccInvocationError`) rather than silently degrading if ECC's contract changes shape — see ADR-010, [[phases/phase-06]]. The command invoked is configurable, never hardcoded, so a broken/missing ECC checkout on one machine can't silently corrupt results on another. |
| Privacy / secrets exposure | Open | Mitigation: local-first execution, redaction — [[11-security]]. At the Phase 6 remainder: `LlmSolvingAgent` can now genuinely send fixture source code to a cloud LLM vendor (Claude/ChatGPT/Gemini) — but only when the user explicitly configures `EEP_LLM_PROVIDER`/`EEP_LLM_API_KEY` for a cloud backend; the local-LLM path (`EEP_LLM_PROVIDER=openai-compatible` + a `localhost` `EEP_LLM_BASE_URL`) sends nothing off the machine, and no provider is ever selected by default (ADR-013). Benchmark fixtures are small, self-authored, non-sensitive code, so the exposure surface today is low; would need reassessment before pointing this at any real/sensitive repository. |
| Excessive evaluation cost (time/compute) | Open | To be monitored once a live comparison run actually executes. Now concretely quantifiable: the Phase 6-remainder design is 3 real-fixture tasks × 9 conditions × 3 repetitions = 81 runs, each potentially several LLM turns against a paid cloud API — real per-run token/dollar cost, not yet measured since no live run has been executed. At Phase 12: the new free `npm run reproduce:smoke` path (27 runs, 1 repetition, a deterministic fake LLM client) exercises the same harness/verifier/metrics/analysis/report/dashboard code paths against genuinely-executed data for the first time — but it is not a live LLM run and has zero cost, so this row's cost concern is unaffected and stays `Open`. |
| Dashboard complexity growing ahead of data-model maturity | Open | Mitigation: dashboard explicitly sequenced after Phase 9 — [[12-dashboard-strategy]]. |
| False confidence in small-sample results | Open | Mitigation: statistical discipline — [[06-evaluation-methodology]]; Phase 5's `aggregateMetricsByName()` deliberately stays non-statistical (mean/median/stddev only, no significance testing) rather than implying rigor it can't back up — see [[phases/phase-05]], ADR-009. |
| Environment isolation is filesystem-copy only, not container/process sandboxed (ADR-007) | Open | Revisited at the Phase 6 remainder, as flagged: `LlmSolvingAgent` now does execute model-authored file writes and run `npm test` against model-authored code. Narrowed, not closed — the tool surface is deliberately bounded and path-clamped (`list_files`/`read_file`/`write_file` reject any path escaping the workspace root; `run_tests` only ever runs the fixture's own fixed `npm test`, never an arbitrary model-supplied command; no generic shell-exec tool exists at all — ADR-013 in [[14-decisions]]), but `run_tests` is still real code execution with only a wall-clock timeout, no CPU/memory/network sandbox. Acceptable for small, self-authored, dependency-light benchmark fixtures; revisit before running this against untrusted/adversarial task content — [[phases/phase-03]], [[phases/phase-04]], [[phases/phase-06]]. |

Add new risks as they're discovered; never delete a risk row, mark it `Closed` with a reason.
